# Участие в проекте

В PR опишите проблему, новое поведение и фактическую проверку. Для ошибки укажите модель станции, прошивку, версии YAM/Luna, отправителя и шаги воспроизведения. Короткий обезличенный лог полезнее полного дампа устройства.

Для изменений Go-кода выполните на Linux из `source/`:

```sh
go test ./...
go vet ./...
```

Для новой модели добавьте проверенный профиль и тесты. Не обходите проверку совместимости подменой model ID. [Пошаговая адаптация](docs/ADD_STATION.md), [полные правила работы с устройством и PR](CONTRIBUTE.md), [сборка и проверки CI](source/BUILD.md).

Для правок документации проверьте команды по исходникам, ссылки и примеры JSON. Отделяйте готовые пакеты YAM v2 от legacy `.yap`, а проверку запуска от слышимого результата. Исторические отчёты в `docs/validation/` сохраняйте как свидетельства конкретной версии.

Не коммитьте токены, ключи, личные адреса, полные пользовательские логи и несогласованные сторонние бинарники. Публикация runtime требует проверки происхождения, лицензий и соответствующих исходников: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
