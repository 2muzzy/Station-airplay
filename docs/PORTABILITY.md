# Что нужно для поддержки новой станции

Новая модель требует проверенного аудиопрофиля и способа запуска через Luna/YAM. Одного добавления model ID в манифест недостаточно: приёмник должен загрузить библиотеки прошивки и открыть общий микшер, пока Алиса работает.

## Что уже разделено по профилям

| Различие | Что выбирает профиль | Зачем это проверять |
|---|---|---|
| model ID | Точное соответствие `models` | Неизвестная модель не должна получать чужие аппаратные настройки. |
| ABI userspace | ARMhf или AArch64 receiver | AArch64-ядро может запускать ARMhf-аудиобиблиотеки. |
| ALSA PCM | `plug:dmix_spk`, `speakers`, `default`, `softvol` или FIFO/aplay | Выход должен смешиваться с Алисой, а не захватывать её устройство. |
| Hostname mDNS | Префикс и источник ID устройства | Avahi добавляет сервис к существующему имени без конфликта адресов. |
| D-Bus | Системные инструменты или пакетный daemon | На некоторых прошивках их нет. |
| Индикация | Без экрана, старый визуализатор или shared-controls | Отсутствие LED не должно мешать аудио; один экран должен иметь понятного владельца. |

Профили и границы реальных проверок: [SHARED_MODELS.md](SHARED_MODELS.md). Общий код находится в `source/profiles.go`, таблица моделей — в `source/service.go`.

## Что остаётся зависимым от прошивки

Проект рассчитан на Linux-станции с ALSA, доступным YAM/Luna runtime и подходящим ядром. Shared-путь требует архитектуру `aarch64` в ответе API, совместимость с ARMv7-супервизором и необходимые Linux-механизмы процессов/namespace. Это не обещание поддержки любой ARM-колонки.

Старые визуализаторы знают конкретную разводку сегментов и колец: Лайт 2 — цифры `0..3`, разделители `DH`/`DL`, три RGB-зоны; Миди — цифры `1..4` и 24 LED. На новой модели не включайте этот renderer без проверки геометрии и API.

Control-enabled ARMhf-приёмник и аудиопрофиль — отдельные уровни поддержки. Рабочий звук не доказывает, что доступны голос, обратная громкость или кнопка Алисы. AArch64 shared-controls пока не квалифицированы.

## Как добавить модель

Следуйте [пошаговой инструкции](ADD_STATION.md) и [правилам вклада](../CONTRIBUTE.md). Сначала подтвердите ABI, общий PCM и hostname. Затем добавьте тесты выбора профиля, соберите пакет и проверьте его на колонке. В PR укажите точную прошивку и отдельно перечислите непроверенные функции.

Сохраняйте один супервизор и общие receiver-сборки для соответствующих ABI. Не создавайте второй менеджер или пакетную копию приёмника для каждого model ID.
